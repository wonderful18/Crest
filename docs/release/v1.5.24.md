# v1.5.24 发布说明

v1.5.24 是 v1.5.23 之后的缺陷修复版本，修复跨数据源自定义 SQL 查询（含中文 CASE WHEN 别名/字面量）执行失败、以及明细表 s2 v2 冻结配置失效的问题。本版本没有新增数据库结构，无需执行升级 SQL。

## 镜像

| 镜像 | Tag |
| --- | --- |
| Crest 后端镜像 | `ghcr.io/sevoniva/crest-service:v1.5.24` |
| Crest 前端镜像 | `ghcr.io/sevoniva/crest-web:v1.5.24` |

## 修复明细

### 跨数据源查询含中文 CASE WHEN 失败 + 连续查询偶发 40001

- 跨数据源（isCross）使用自定义 SQL，含中文等非 ASCII 字符串（如 `CASE d1 WHEN 's' THEN '中文' ELSE '其他' END AS 中文列`）时，预览/保存数据集报错 `SQL执行失败`，后端日志显示生成的 SQL 带有 `_UTF-8'中文'` 前缀，MySQL 不认识该语法；连续多次查询后会偶发 `连接无效，pool error Timeout waiting for idle object` 并返回 40001。
- 根因有二：
  - **`_UTF-8` 前缀注入**：Calcite 在 SQL planning 阶段会给非 ASCII 字符串字面量加 `_UTF-8'xxx'` 前缀，MySQL 不识别。`CalciteProvider.fetchResultField` / `fetchTableField` 的跨源分支原本用 `CalciteConnection.prepareStatement`，会触发该注入。
  - **连接池泄漏**：上述两个跨源分支用 `take()` 借出连接后未 `close`，每次跨源查询/取字段泄漏一个物理连接，连接池耗尽后下一次 `getConnectionFromPool` 借连接超过 5s 超时，抛 40001。
- 修复：
  - `fetchResultField` / `fetchTableField` 跨源分支改为用 `getConnectionFromPool` 返回的底层 MySQL JDBC 连接直接执行，并把虚拟 schema（`s_a_xxx.`）替换为真实库名，绕过 Calcite 的 `_UTF-8` 注入；同时用 `try-with-resources` 确保连接归还，杜绝泄漏。
  - `SqlUtils.addSchema` 渲染后清理残留的 `_UTF-8'` 前缀（含正则兜底覆盖 `_UTF8'` 等），并将 Calcite Lex.JAVA 把 `LIMIT N` 转出的 `FETCH NEXT N ROWS ONLY` 还原为 `LIMIT N`。
  - 新增 `SqlUtils.convertSingleQuotedAliases`：把 `AS '别名'`（单引号字符串字面量）/`AS "别名"` 统一转为反引号 `` AS `别名` ``，因为 Lex.JAVA 下单/双引号不能做别名；`Provider`、`CalciteProvider.transSqlDialect` 同步调用。
  - 新增 `NO_CHARSET_FACTORY`（覆盖 `supportsCharSet()` 返回 false），所有数据源类型的 `JdbcSchema.create` 套用，避免 Calcite `toSqlString` 再加 `_UTF-8` 前缀。
  - Calcite 连接 Lex 由 `JAVA` 调整为 `MYSQL`，并设置 `CONFORMANCE=MYSQL_5`，更贴近 MySQL 方言。
- 新增 `SqlUtilsTest` 覆盖别名转换、`_UTF-8` 清理、`LIMIT` 还原、schema 前置等关键路径，将本次失败 SQL 固化为回归用例。

### 明细表 s2 v2 冻结配置失效

- 明细表配置冻结行/列或汇总行冻结后不生效。根因是 `@antv/s2` 升级到 v2 后，冻结配置从顶层属性（`frozenColCount` / `frozenRowCount` / `frozenTrailingRowCount`）改为 `frozen` 嵌套对象（`colCount` / `rowCount` / `trailingRowCount`）。`table-info`、`table-normal`、`common_table` 仍写顶层属性，v2 不再读取。
- 修复：统一改写为 `options.frozen = { colCount, rowCount, trailingRowCount }`，汇总行冻结用 `...(options.frozen || {})` 合并避免覆盖已有配置。

## 验证

- 跨数据源自定义 SQL 含 `CASE WHEN ... THEN '中文' ELSE '其他' END AS 中文列` 的数据集，预览、保存数据集、运行均成功，后端日志不再出现 `_UTF-8'` 前缀。
- 连续多次跨源中文查询不再偶发 40001 / 连接池超时。
- 明细表冻结行/列及汇总行冻结恢复正常生效。
- 全量回归：前端表格相关 60 项单测全过；后端 core-backend 724 项测试无新增失败（新增 `SqlUtilsTest` 7 项全过）；`Quota2SQLObjTest` 2 项「失败」经对照实验确认为容器默认 UTC 时区所致，与本次改动无关，生产镜像已设 `Asia/Shanghai` 不受影响。

## 升级说明

- 从 v1.5.23 升级到 v1.5.24 只需要替换前后端镜像，不需要新增升级 SQL。

## 兼容性

- 仅修改跨源 SQL 执行/渲染路径与明细表冻结配置适配，不影响数据结构与其他组件行为。
