# v1.5.18 发布说明

v1.5.18 是 v1.5.17 之后的安全补丁版本，修复系统管理模块安全审计报告（docs/SYSTEM_MANAGEMENT_AUDIT_REPORT.md）中遗留的 6 个高危问题。本版本没有新增数据库结构，无需执行升级 SQL。

## 修复明细

### SSO 安全三连修复

1. **SSO callback nonce 校验**（审计 #3）：callback 阶段从 id_token 中提取 nonce 声明，与登录发起时缓存的 nonce 比对。nonce 不匹配时拒绝登录。id_token 未包含 nonce 时记录告警日志并继续（兼容不支持 nonce 的 IdP）。

2. **SSO id_token claims 校验**（审计 #4）：现在会校验 id_token 的 issuer（如已配置 issuer）、audience（与 clientId 比对）和 expiration 声明。防止攻击者伪造 id_token payload 中的用户身份信息。

3. **SSO token 过期时间**（审计 #5）：SSO 登录生成的 token 现在设置 24 小时有效期（与本地登录一致）。密码修改后旧 token 将在过期后失效。此前 token 永不过期。

### SQL 注入修复

4. **resourceScopeSql resourceType 白名单**（审计 #1，部分修复的补全）：resourceScopeSql 现在对 resourceType 执行白名单校验（datasource、dataset、panel、screen），并对列名参数（creatorColumn、resourceIdColumn、orgColumn）执行格式校验，防止通过列名注入 SQL。

5. **communityScopeSql uid 数字校验**（审计 #2）：现在会校验 uid 字符串为纯数字后才拼接到 SQL。非数字值会跳过范围过滤并记录告警日志。此前使用单引号替换方式，安全性不足。

### 数据可靠性修复

6. **用户导入异常收集**（审计 #6）：批量导入用户时，异常现在会记录告警日志，并在返回结果中包含每条失败记录的账号和错误原因。此前 `catch (RuntimeException ignored)` 完全吞掉异常，管理员无法得知导入失败的具体原因。

## 升级说明

- 从 v1.5.17 升级到 v1.5.18 时只需要替换前后端镜像，不需要新增升级 SQL。
- 从 v1.5.16 或更早版本升级时，请先执行对应升级 SQL，再替换 v1.5.18 前后端镜像。
- 升级前建议备份元数据库和运行目录。

## 兼容性

- SSO nonce 校验：如果身份提供方不支持 OIDC nonce，系统会记录告警日志并继续登录流程，不会阻断现有 SSO 登录。
- SSO id_token claims 校验：如果未配置 issuer，iss 声明校验会跳过。aud 声明必须与 clientId 匹配。
- SSO token 过期：升级后已登录的 SSO 用户需要重新登录（旧 token 不含 exp 声明，会在下次校验时被拒绝）。
- 用户导入返回结果新增 `errors` 字段，前端需要适配展示失败详情。
