# v1.5.25 发布说明

v1.5.25 是 v1.5.24 之后的缺陷修复版本，修复导出 Excel 整数列带多余小数点、以及日期列带多余 `00:00:00` 的问题。本版本没有新增数据库结构，无需执行升级 SQL。

## 镜像

| 镜像 | Tag |
| --- | --- |
| Crest 后端镜像 | `ghcr.io/sevoniva/crest-service:v1.5.25` |
| Crest 前端镜像 | `ghcr.io/sevoniva/crest-web:v1.5.25` |

## 修复明细

### 导出 Excel 整数列带多余小数点

- 导出明细时，整数类型字段的值被 `Double.parseDouble` 转成 double 写入 Excel，POI 内部以 `7.0` 存储。原格式 `0.######` 理论上整数不显示小数点，但在部分 Excel/WPS 版本中仍显示 `7.0`（带多余小数点）。
- 根因：POI `setCellValue(long)` 内部仍以 double 存储，格式 `0.######` 对 `7.0` 的显示取决于 Excel 版本，行为不一致。
- 修复：整数类型字段强制设 `"0"` 格式（纯整数，无小数位），并用 `longValueExact` 写入，确保所有 Excel 版本显示 `7` 不带 `.0`；FLOAT 类型保留 double 和原格式。
- 两条导出路径都已修复：`ChartDataServer.setExcelData`（table-info/table-normal 分支 + 其他视图分支）与 `ExportCenterDownLoadManage.setExportCellValue`。

### 导出 Excel 日期列带多余 00:00:00

- 日期类型字段导出时，数据源返回 `"2026-05-28 00:00:00"`（纯日期 + 零时分秒），原样写入导致 Excel 显示多余的时分秒。
- 修复：新增 `normalizeDateString`，对 TIME 类型字段，若值形如 `yyyy-MM-dd 00:00:00`（零时分秒）截成 `yyyy-MM-dd`；带实际时分秒的完整 datetime 保持不变。
- 两条导出路径都已接入。

## 验证

- 导出明细 Excel，整数列显示 `7`、`21`（不再 `7.0`、`21.0`）。
- 日期列显示 `2026-05-28`（不再 `2026-05-28 00:00:00`）。
- FLOAT 列保持原样（带小数）。

## 升级说明

- 从 v1.5.24 升级到 v1.5.25 只需要替换前后端镜像，不需要新增升级 SQL。

## 兼容性

- 仅修改导出 Excel 的数值/日期写入逻辑，不影响数据结构与其他组件行为。
