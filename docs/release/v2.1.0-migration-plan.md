## Migration Scripts Required

The current v2.0.3 tree has full schema files and v2.0.x incremental scripts, but no direct production upgrade from v1.5.14 to v2.x. v2.1.0 must add and validate:

- `installer/upgrade-sql/v1.5.14_to_v2.1.0_mysql.sql`
- `installer/upgrade-sql/v2.0.3_to_v2.1.0_mysql.sql`
- `installer/upgrade-sql/v2.0.3_to_v2.1.0_ob_mysql.sql`
- `installer/upgrade-sql/v2.0.3_to_v2.1.0_ob_oracle.sql`

- `installer/upgrade-sql/v2.1.0_full_schema_ob_mysql.sql`

The `v1.5.14_to_v2.1.0_mysql.sql` script must migrate existing production data. It must not use a full schema as an upgrade path.

## Data Migration Coverage

The v1.5.14 to v2.1.0 migration must explicitly cover:

- Users, roles, permissions, organizations, and system settings.
- Datasources, drivers, datasets, dataset fields, dataset SQL, and cache/task metadata.
- Charts, chart fields, chart styles, chart filters, and table summary settings.
- Visualizations, components, snapshots, linkage, jump configuration, public share links, and tickets.
- Uploaded resources, fonts, templates, media, and export tasks.
- Audit data and operational records that still exist in the 2.x schema.

Each mapped table must have a preflight check and post-upgrade verification query. Data that cannot be migrated automatically must be listed with a manual handling step.

## Security Gate

v2.1.0 cannot regress from the v1.5.14 security baseline. Current initial findings that must be resolved or explicitly justified:

- `template.accessKey` is still initialized as `crest` in v2.0.3 full-schema SQL; the v2.1 working branch adds `v2.0.3_to_v2.1.0_*` cleanup scripts for existing v2.0.3 databases and `v2.1.0_full_schema_*` files with an empty `template.accessKey` default.
- The v2.0.3 baseline had `crest.default-link-pwd` fallback to `crest-link-pwd`; the v2.1 working branch now derives a non-public fallback from explicit link-secret configuration, `CREST_AES_KEY`, `CREST_TOKEN_SECRET`, or development-only runtime entropy.
- The v2.1 working branch aligns `calcite-core` to `1.42.0`, `netty` to `4.2.15.Final`, and Jackson dependency management to `jackson-bom 2.22.0`, matching the v1.5.14 security dependency baseline.
- Several v1.5.14 security tests are absent from v2.0.3.

## Release Blockers

Do not create a stable v2.1.0 tag while any item below remains unresolved:

- Commit-level migration table is incomplete.
- Any feature is moved by bulk replacement instead of reviewed, scoped porting.
- v1.5.14 production data migration is not tested on a real or desensitized database.
- SAST, SCA, or secret scanning is missing or has unresolved findings.
- Full-schema defaults and upgrade-script defaults differ.
- Browser validation has console errors or warnings on the migrated build.
- Backend logs contain new exception stacks during validation.
- Public documentation contains internal environment details or temporary package wording.
