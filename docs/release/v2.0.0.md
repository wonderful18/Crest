# Crest v2.0.0 发布说明

发布日期：2026-06-18

Crest v2.0.0 是面向生产部署和多数据库运行的版本。本版本补齐前后端分离部署、Kubernetes 生产拓扑、任务队列、共享存储、OceanBase 系统库和业务数据源支持，并随离线包交付初始化 SQL 与增量升级 SQL。MySQL 仍为默认系统库；未显式配置 `CREST_DB_TYPE=ob-mysql` 或 `CREST_DB_TYPE=ob-oracle` 时，现有 MySQL 部署行为不变。

## 离线包

`crest-offline-*` 是完整离线安装包，包含安装脚本、配置模板、Docker Compose 文件、Crest 后端镜像、Crest 前端镜像、MySQL 镜像、可选 Prometheus/Grafana 镜像、初始化 SQL、升级 SQL 和离线安装说明。

`crest-app-images-*` 是应用镜像升级包，包含 Crest 后端镜像、Crest 前端镜像、初始化 SQL、增量升级 SQL 和镜像加载说明，不包含 MySQL、Prometheus、Grafana 镜像，也不包含完整安装脚本。已有环境只需要替换应用服务时，可使用该包。

## 主要变化

- 支持按运行角色拆分后端服务：API、scheduler、worker 可独立部署；生产模式下可通过环境变量控制每类节点职责。
- 新增 Kubernetes 生产部署清单，包含 API、scheduler、worker、Redis、HPA、PDB、共享存储和可观测性资源。
- 新增 Redis Stream 任务队列，覆盖导出、数据源同步、数据集同步、定时报表和数据填报任务，并支持 pending 消息认领、状态恢复和死信处理。
- 新增 Redis 集群、分布式锁和 WebSocket 广播支持，多副本部署下可保持缓存、调度和实时消息一致。
- 新增统一存储服务，导出文件、远程 Excel、可视化导出、字体、驱动包和共享资源可写入共享目录。
- 支持 Crest 系统库使用 OceanBase MySQL 或 OceanBase Oracle。OceanBase 按外部企业数据库处理，支持 OBProxy 和 observer 直连。
- 业务数据源新增 OceanBase MySQL 类型，并完善 OceanBase Oracle 的连通性、元数据读取、SQL 预览、分页查询、数据集预览和图表查询。
- 后台系统设置、审计日志、缓存任务、站点设置、引擎设置和可观测性页面完成多数据库语境下的文案和展示修正。
- 完成前端依赖、Code Scanning 告警和 Java 覆写标记治理，降低安全扫描和代码质量回归风险。
- 公开文档重新整理，补齐 OceanBase、平台管理、研发效能指标、离线包和发布流程说明。
- Release workflow 增加离线包和应用镜像包内容校验，确保初始化 SQL、增量 SQL、镜像归档和加载脚本随包交付。

## 修复内容

- 修复 OceanBase Oracle 下审计日志时间筛选、状态展示、失败原因和资源类型渲染异常的问题。
- 修复 OceanBase Oracle 下图表字段 SQL、布尔筛选、空值字段、分页查询、资源发布清理和 SQL 补全相关兼容问题。
- 修复数据集自定义 SQL 表名补全、字段探测、跨源默认值和 SQL 片段拼接在部分数据源下不稳定的问题。
- 修复导出完成通知、导出中心轮询、远程 Excel 下载、共享资源读取和自定义驱动存储在多副本部署下不稳定的问题。
- 修复生产启动时清空 Redis 缓存、重复领取队列消息、旧任务状态覆盖和任务完成检查角色不一致的问题。
- 修复后台用户列表返回多余字段、请求体不可读异常分类和绑定参数异常提示不明确的问题。

## 升级说明

升级前必须完成以下准备：

- 备份 Crest 系统库；
- 备份运行目录和 `.env`；
- 记录当前前后端镜像、数据目录和外部数据库连接信息；
- 如使用多副本部署，确认 Redis、共享存储和业务库连接数满足新拓扑要求。

全新 MySQL 安装不需要手动执行 `upgrade-sql/`。安装脚本会继续按默认 MySQL 路径初始化系统库。

全新 OceanBase 安装按外部数据库处理。生产环境建议由 DBA 先创建租户、数据库或 schema、账号和权限，再使用 `obclient --default-character-set=utf8mb4` 按文件名顺序执行离线包中的 `init-sql/ob-mysql/` 或 `init-sql/ob-oracle/`。应用配置中保持 `CREST_FLYWAY_ENABLED=false`，服务启动时只连接已初始化的系统库。

已有 v1.5.11 环境升级到 v2.0.0 时，先按系统库类型执行本版本增量 SQL，再替换前后端镜像或使用应用镜像升级包。

MySQL 系统库执行：

```text
upgrade-sql/v2.0.0_export_task_queue_mysql.sql
upgrade-sql/v2.0.0_datasource_sync_task_queue_mysql.sql
upgrade-sql/v2.0.0_dataset_sync_task_queue_mysql.sql
upgrade-sql/v2.0.0_dataset_sync_task_queue_metadata_mysql.sql
upgrade-sql/v2.0.0_scheduled_task_queue_state_mysql.sql
upgrade-sql/v2.0.0_audit_log_filter_index_mysql.sql
```

OceanBase MySQL 系统库执行：

```text
upgrade-sql/v2.0.0_export_task_queue_ob_mysql.sql
upgrade-sql/v2.0.0_datasource_sync_task_queue_ob_mysql.sql
upgrade-sql/v2.0.0_dataset_sync_task_queue_ob_mysql.sql
upgrade-sql/v2.0.0_dataset_sync_task_queue_metadata_ob_mysql.sql
upgrade-sql/v2.0.0_scheduled_task_queue_state_ob_mysql.sql
upgrade-sql/v2.0.0_audit_log_filter_index_ob_mysql.sql
```

OceanBase Oracle 系统库执行：

```text
upgrade-sql/v2.0.0_export_task_queue_ob_oracle.sql
upgrade-sql/v2.0.0_datasource_sync_task_queue_ob_oracle.sql
upgrade-sql/v2.0.0_dataset_sync_task_queue_ob_oracle.sql
upgrade-sql/v2.0.0_dataset_sync_task_queue_metadata_ob_oracle.sql
upgrade-sql/v2.0.0_scheduled_task_queue_state_ob_oracle.sql
upgrade-sql/v2.0.0_repair_seed_text_encoding_ob_oracle.sql
upgrade-sql/v2.0.0_audit_log_filter_index_ob_oracle.sql
```

从 v1.5.7 及更早版本升级时，先执行历史结构补齐 SQL，再执行上面的 v2.0.0 增量 SQL：

```text
upgrade-sql/v1.5.7_to_v1.5.8.sql
```

从 v1.5.4 升级时，还需要先执行：

```text
upgrade-sql/v1.5.4_to_v1.5.5.sql
```

OceanBase 连接可使用 OBProxy 或 observer。OBProxy 用户名使用 `用户@租户#集群`，observer 直连使用 `用户@租户`。两种方式均需要在 `CREST_DB_HOST`、`CREST_DB_PORT`、`CREST_DB_USERNAME` 和 `CREST_DB_PASSWORD` 中显式配置。
