# v1.5.32 发布说明

v1.5.32 是 v1.5.31 之后的修复版本。修复分享链接升级弹框、透视表合计为空、汇总表自定义公式列为空、明细表自定义排序跨页乱序四个问题。**本版本没有新增数据库结构,无需执行升级 SQL。**

## 镜像

| 镜像 | Tag |
| --- | --- |
| Crest 后端镜像 | `ghcr.io/sevoniva/crest-service:v1.5.32` |
| Crest 前端镜像 | `ghcr.io/sevoniva/crest-web:v1.5.32` |

## 修复

### 分享链接打开时不提示系统升级弹框

- 分享链接(`/link/:uuid`)面向查看者,弹出"系统有升级,请点击刷新页面"提示体验差且无意义。
- 根因:`service.ts` 的 `executeVersionHandler` 在响应头 `x-crest-execute-version` 变化时弹升级框,不分场景。
- 修复:`executeVersionHandler` 开头判断当前路由是否 `/link/` 分享链接路径,是则直接跳过不提示。普通编辑页行为不变。

### 透视表行/列合计均为空

- 透视表在任何配置下行合计、列合计都显示为空。
- 根因:`table-pivot.ts` 的 `getAggregationAndCalcFuncByQuery` 及自定义聚合函数解构用旧字段名 `isRowTotal`/`isColTotal`,但 S2 v2.7.1 的 `TotalStatus` 字段名为 `isRowGrandTotal`/`isColGrandTotal`,导致合计节点恒匹配不到聚合配置,`getTotalValue` 返回 undefined,合计显示空。
- 修复:对齐 S2 v2.7.1 的 `TotalStatus` 字段名,新增 `normalizeTotalStatus` 兼容旧名,所有 `getTreeCustomCalcResult`/`getGridCustomCalcResult` 入口归一化后统一用 `isRowGrandTotal`/`isColGrandTotal`。

### 汇总表自定义公式列为空

- 汇总表新增自定义公式列(自定义列名 + 公式,如"交付全周期"= 开发周期+测试周期+验收周期),每一行应按公式算出值,但数据行显示为空(仅总计行有值)。
- 根因:`appendSummaryColumnsToS2Config` 对每个数据行把自定义汇总列填成空值占位 `--`,只有总计行用后端 `summaryColumnResult` 填值;且公式 `originName` 带前导 `=`(类 Excel 写法),前端求值器白名单不接受 `=`。
- 修复:`tableSummaryColumns.mjs` 新增 `evalSummaryColumnFormula`(把 `[fieldId]` 占位替换为该行字段值后白名单求值,strip 前导 `=`,纯算术字符 + 单引号转义)+ `buildIdToEngineFieldMap`(从 xAxis/xAxisExt/yAxis 构建 id→engineFieldName 映射);`appendSummaryColumnsToS2Config` 对 custom 公式列逐行算值;`table-normal.ts`/`table-info.ts` 构建映射并传入。总计行逻辑不变。

### 明细表自定义排序跨页乱序

- 明细表分页时,`custom_sort` 字段的同维度数据跨页重复/穿插(如"开发一室→平台研发室→开发一室")。
- 根因:`custom_sort` 字段不进 SQL `ORDER BY`(`Utils.joinSort` 只放行 asc/desc),SQL 先按无关默认字段 `ORDER BY` + `LIMIT` 取一页,再在页内做内存 `customSort`。跨页数据分散到不同页,翻页时同一维度重复出现、整体乱序。
- 修复:`Dimension2SQLObj.java` 对 `custom_sort` 维度字段生成 `ORDER BY CASE <fieldAlias> WHEN 'v1' THEN 0 ... ELSE N END ASC`,下推到 SQL,让分页 `LIMIT` 在全局自定义顺序上切分;配合 `sortPriority` 重排按优先级生效。ES 数据源跳过(无 CASE 语法,维持内存排序);字符串值单引号转义防注入。
- 验证:新增 `Dimension2SQLObjTest` 单测覆盖 CASE 生成/单引号转义/ES 跳过;端到端接口分页测试确认跨页不乱序。
