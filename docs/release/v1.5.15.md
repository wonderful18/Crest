# Crest v1.5.15 发布说明

发布日期：2026-07-04

Crest v1.5.15 是 v1.5.14 之后的 1.5 LTS 稳定补丁版本，修复大屏发布时提示"资源不存在"的回归问题。本版本没有新增数据库结构，无需执行升级 SQL。

```text
crest-offline-v1.5.15-linux-arm64.tar.gz
crest-app-images-v1.5.15-linux-amd64.tar.gz
crest-app-images-v1.5.15-linux-arm64.tar.gz
crest-source-v1.5.15.tar.gz
crest-v1.5.15-checksums.txt
crest-app-images-v1.5.15-checksums.txt
```

GitHub Release 页面会自动提供 `Source code (zip)` 和 `Source code (tar.gz)`。`crest-source-v1.5.15.tar.gz` 是发布流程额外生成的命名源码包，便于归档和交付。

```text
ghcr.io/sevoniva/crest-web:v1.5.15
```

支持架构：

```text
linux/amd64
```

`crest-offline-*` 是完整离线安装包，包含安装脚本、配置模板、Docker Compose 文件、Crest 后端镜像、Crest 前端镜像、MySQL 镜像、可选监控组件配置、升级 SQL 和离线安装说明。

`crest-app-images-*` 是应用镜像升级包，仅包含 Crest 后端镜像、Crest 前端镜像、增量升级 SQL 和加载说明，不包含 MySQL、Prometheus、Grafana 镜像，也不包含完整安装脚本。已有环境只需要替换前后端应用服务时，可使用该包。

## 与 v1.5.14 的主要差异

### 大屏发布

- 修复大屏发布时提示"资源不存在"的问题。v1.5.14 的安全加固为 `CoreVisualizationManage.dvRestore` 增加了 `requireVisualizationAccess` 校验，该方法通过 `mapper.selectById` 查询主表 `bi_visualization` 来校验资源存在性和创建者权限。但发布流程 `updatePublishStatus` 在同一事务内先调用 `removeDvCore` 物理删除主表记录（`DELETE FROM bi_visualization`），再调用 `dvRestore` 从镜像表 `bi_visualization_snapshot` 恢复主表，导致 `dvRestore` 内的主表查询必然返回空并抛出 `resource not exist`，用户在前端看到"资源不存在"。移除 `dvRestore` 内冗余的主表存在性校验，权限校验由调用方保证：
  - `updatePublishStatus` 在发布前通过 `innerEdit` 已调用 `requireVisualizationAccess` 校验创建者权限；
  - `recoverToPublished` 通过 `requireVisualizationManage` 已校验资源权限。

## 兼容性说明

- 本版本没有新增数据库表、字段或升级 SQL。
- 大屏发布、取消发布、恢复到已发布状态的行为与 v1.5.14 之前一致。
- v1.5.14 的安全加固在其他路径上的权限校验保持不变，仅修正 `dvRestore` 在发布事务内主表已被删除场景下的错误校验。

## 验证范围

- 后端编译验证：`core-backend` 模块编译通过。
- 发布流程验证：大屏从已保存未发布状态发布为已发布，不再提示"资源不存在"，主表数据由镜像表正确恢复。
- 取消发布验证：取消发布状态切换正常。
- 恢复到已发布验证：`recoverToPublished` 调用 `dvSnapshotRecover` 正常，权限校验不受影响。
- 跨环境导入验证：大屏从源环境导出后导入目标环境，发布操作正常完成。
