# v1.5.22 发布说明

v1.5.22 是 v1.5.21 之后的缺陷修复版本，修复组件/画布上传背景图后图片加载 404 导致不显示的问题。本版本没有新增数据库结构，无需执行升级 SQL。

## 镜像

| 镜像 | Tag |
| --- | --- |
| Crest 后端镜像 | `ghcr.io/sevoniva/crest-service:v1.5.22` |
| Crest 前端镜像 | `ghcr.io/sevoniva/crest-web:v1.5.22` |

## 修复明细

### 背景图上传后加载 404

- 组件/画布上传背景图后，缩略图不显示、画布上背景图不生效，浏览器控制台报图片 404。上传（POST）本身成功、文件正常落盘到 `static-resource` 目录，但图片 GET 请求返回 404。
- 根因在 `deploy/split/nginx/crest.conf` 的静态资源正则 location `~* \.(?:js|css|png|jpg|...)$`。nginx 正则 location 优先级高于 `/api/v1/` 前缀 location，当浏览器 GET `/api/v1/static-resource/<id>.jpg` 时，URL 以 `.jpg` 结尾命中正则，执行 `try_files $uri =404` 在前端静态目录找不到文件而返回 404。又因 `access_log off`，404 不记日志，后端侧无任何痕迹。
- 修复：正则加 `^(?!/api/)` 负向先行断言，`/api/` 下的图片请求不再被拦截，正常代理到后端。前端自身静态资源（`/assets/*.js` 等）不受影响，仍走 `try_files` + 30 天缓存。
- 此前 v1.5.20、v1.5.21 两次针对前端 `BackgroundOverallCommon.vue` 状态字段的修复（`applyUploadedBackground` 自动启用 `backgroundImageEnable` 并设置 `backgroundType='outerImage'`）保留，前端状态链路本身正确，本次定位到真正的 nginx 路由根因。

## 验证

- 重建前端镜像并重启 `crest` 容器后：`GET /api/v1/static-resource/<id>.jpg` 返回 200（修复前 404）；前端静态资源 `/assets/*.js` 仍 200 且带 `Cache-Control: max-age=2592000` 缓存头。
- 浏览器中上传组件/画布背景图：属性面板立即显示缩略图，画布上背景图正常生效。

## 升级说明

- 从 v1.5.21 升级到 v1.5.22 只需要替换前后端镜像，不需要新增升级 SQL。

## 兼容性

- 仅修改 nginx 路由规则，不影响后端逻辑与数据；前端静态资源缓存行为不变。
