# v1.5.33 发布说明

v1.5.33 是 v1.5.32 之后的性能优化与修复版本。优化前端组件懒加载降低首屏体积,并改进导出应用模板的错误提示。**本版本没有新增数据库结构,无需执行升级 SQL。**

## 镜像

| 镜像 | Tag |
| --- | --- |
| Crest 后端镜像 | `ghcr.io/sevoniva/crest-service:v1.5.33` |
| Crest 前端镜像 | `ghcr.io/sevoniva/crest-web:v1.5.33` |

## 优化

### 前端组件懒加载(P0 性能优化)

- 打开数据大屏/仪表盘/分享链接/数据集较慢,首屏需下载解析大量组件代码。
- 根因:`utils/components.ts` 所有自定义组件静态 import,首屏 bundle 打入 tinymce(1180KB)/exceljs(914KB)/echarts(887KB)/video.js(477KB) 等重组件。
- 修复:`utils/components.ts` 所有自定义组件改 `defineAsyncComponent` 按组件名按需加载;`views/chart/components/views/index.vue` 的 `ChartComponentG2Plot`(echarts)与 `ChartComponentS2`(antv-s2)改 `defineAsyncComponent` 按图表类型按需加载。
- 效果:首屏 preload 从 ~7MB 降到 3.6MB(节省约 3.4MB),tinymce/exceljs/echarts/video.js 移出首屏,分享链接/纯图表大屏首屏体积大幅下降。

## 修复

### 导出应用模板错误提示不明确

- 导出应用模板时报"导出范围包含无效数据集"但无法定位是哪个数据集。
- 根因:`validateAppExportScope` 三处错误都用笼统提示"包含无效数据集",不显示具体数据集名称;且错误信息过长(>200字符)被 `safeClientMessage` 降级为"请求处理失败"。
- 修复:错误提示改为带具体数据集名称(查 `dataset_group` 表),已删除的数据集显示 ID;信息精简到 200 字符以内。用户遇到问题可直接看到是哪个数据集导致,便于排查。
