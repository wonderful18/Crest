# v1.5.27 发布说明

v1.5.27 是 v1.5.26 之后的修复与功能改进版本。修复 v1.5.26 跨源连表查询失败、导出 Excel 小数显示异常，并改进数据集缓存按天自定义时点（改为纯前端实现，无需数据库迁移）。**本版本没有新增数据库结构，无需执行升级 SQL。**

## 镜像

| 镜像 | Tag |
| --- | --- |
| Crest 后端镜像 | `ghcr.io/sevoniva/crest-service:v1.5.27` |
| Crest 前端镜像 | `ghcr.io/sevoniva/crest-web:v1.5.27` |

## 修复

### 跨源连表查询失败（Unknown database 's_a_xxx'）

- 跨源连表关联查询时，`CalciteProvider` 只替换了第一个数据源的虚拟 schema（`s_a_1`），第二个数据源的虚拟 schema 未替换导致 MySQL 报 `Unknown database`。
- 修复：`fetchResultField` 和 `fetchTableField` 两处跨源分支改为遍历 `dsList` 所有 entry，替换每个虚拟 schema 为真实库名。`CalciteProvider.java`。

### 跨源 SQL 语法错误（OFFSET N ROWS LIMIT N）

- Calcite `toSqlString` 生成 SQL 标准语法 `OFFSET N ROWS FETCH NEXT M ROWS ONLY`，MySQL 不认识。已有的 `FETCH NEXT → LIMIT` 替换只处理了无 OFFSET 的情况，带 OFFSET 时残留 `OFFSET N ROWS` 导致语法错误。
- 修复：`SqlUtils.addSchema` 增加 `OFFSET N ROWS FETCH NEXT M ROWS ONLY → LIMIT M OFFSET N` 替换，残留 `OFFSET N ROWS` 去除。`SqlUtils.java`。

### 导出 Excel FLOAT 小数显示

- v1.5.25 只修了 INTEGER 类型整数去小数点，FLOAT 类型值为整数时仍显示 `0.`（格式 `0.######` 对 double 0.0 渲染为 `0.`），FLOAT 小数值被误取整（如 `3.14` 显示成 `3`）。
- 修复：FLOAT 整数值用纯整数格式 `"0"` 写入，非整数值显式用 `"0.######"` 小数格式写入。`ChartDataServer.java`（2 处）与 `ExportCenterDownLoadManage.java`（1 处）。

### 保存同步任务后时点丢失

- 前端保存 payload `buildDatasetSyncTaskPayload` 漏传 `simpleCronHour` 字段，导致后端存空。已补传。

## 新增

### 数据集缓存按天自定义时点（纯前端方案，无数据库迁移）

- 数据集缓存的「按天更新」简单调度此前固定在凌晨 0 点执行，现支持选择 0-23 点的任意时点（如每天早上 8 点）。
- **纯前端实现，后端和数据库零改动**：利用后端已有的 `syncRate=CRON` 模式（后端 `normalize()` 对 CRON 模式直接用前端传的 cron 表达式，不重算），前端在「天 + 时点」时生成完整 cron 表达式（如 `0 0 8 1/1 * ? *`）存入 `cron` 字段。加载时反解回 UI 显示。
- 不新增数据库字段、不执行 Flyway 迁移。从 v1.5.25 直接升级只需替换镜像。

### 明细表合并单元格大小写不敏感

- 明细表合并单元格时按大小写不敏感比较，`Pos系统/POS系统/pos系统` 这类仅大小写不同的相邻值合并为一行。合并段中央单元格统一显示大写形式。

### 数据集字段上下移

- 数据集字段列表支持上移/下移调整顺序，导出 Excel 列按调整后的顺序排列。

## 验证

- 数据集缓存按天选 8 点保存后重开仍为 8 点，DB `cron='0 0 8 1/1 * ? *'`、`sync_rate='CRON'`。
- 跨源连表关联查询（两个数据源 JOIN）成功执行，不再报 `Unknown database`。
- 导出 FLOAT 整数 `12.0`→`12`、`0`→`0`；小数 `3.14`→`3.14`。
- 明细表含 Pos/POS/pos 相邻值合并为一行。

## 升级说明

- **从 v1.5.25 或 v1.5.26 升级到 v1.5.27 只需要替换前后端镜像，不需要新增升级 SQL。**
- 默认镜像为 `ghcr.io/sevoniva/crest-service:v1.5.27` 和 `ghcr.io/sevoniva/crest-web:v1.5.27`。

## 兼容性

- 后端和数据库结构零改动，既有任务行为不变。
- 旧的 SIMPLE_CRON + day 任务（0 点）加载后仍正常显示，用户重新保存后切换为 CRON 模式带时点。
