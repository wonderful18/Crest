## Implemented Scope

- Ported the v1.5.14 visualization background-image fixes into the v2.1 frontend runtime and added regression tests.
- Restored public-share visualization jump routing so embedded reports can jump to a public target visualization without reusing the source access credential.
- Added single-sided time-range query support for start-only and end-only filters.
- Added editable fixed date inputs for time-range query configuration.
- Added table summary metric columns, summary calculations, display formatting, export support, and frontend/backend regression tests.
- Fixed table header sort tooltip behavior and added targeted frontend tests.
- Fixed dynamic date preset submission defaults.
- Stabilized template import/export flow and resource-tree refresh behavior.
- Added legacy canvas default normalization for imported or historical visualization components.
- Hardened initialization secrets, share-link secret fallback, dependency baselines, and template resource storage validation.
- Hardened remaining v1.5.14 security parity items for upload-size limits, audit expression parsing, Excel watermark rendering, safe logout URL handling, and Calcite shared-connection lifecycle handling.
- Updated the backend logging dependency baseline so `logback-core` resolves to `1.5.33`.
- Added v2.1 full-schema SQL files and upgrade SQL files for supported v2.0.3 database paths.
- Added a MySQL entrypoint script for v1.5.14 to v2.1.0 upgrades.

## Release Blockers

Do not create the stable `v2.1.0` tag until the following items are closed:

- Execute and verify `v1.5.14_to_v2.1.0_mysql.sql` against a real or desensitized v1.5.14 business database.
- Execute and verify the OceanBase v2.0.3 upgrade scripts against their matching database engines.
- Execute and verify the OceanBase v2.1.0 full-schema scripts against empty databases for their matching engines.
- Re-run browser validation against an upgraded database, not only the current local development data.
- Check backend logs during browser validation and confirm there are no new exception stacks.
- Run the branch `security-gates.yml` workflow after it is available on the default branch, or run an equivalent CI security gate with archived logs.
- Re-run recursive Maven OSV scanning in CI or through a stable Maven mirror. Local recursive scanning was interrupted by Maven Central `429` responses and standalone reactor-module resolution limits; direct Maven dependency evidence and no-resolve OSV scanning are recorded, but the recursive CI gate still needs an archived pass.

## Release Decision

Current status: not ready for stable release.

The code branch has passed local build, frontend checks, targeted backend tests, dependency scans, SAST, Release Guard, and MySQL baseline SQL execution. The remaining blockers are real or desensitized business-data migration validation, OceanBase SQL execution validation, and final end-to-end validation on an upgraded environment. After those are complete, the release can proceed to tag and publish review.
