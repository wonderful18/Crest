# 1.5.6 开发期安全加固记录

## 分支定位

- 基线分支：`dev`
- 工作分支：`security/1.5.6-hardening`
- 适用阶段：1.5.6 功能开发阶段
- 处理原则：不修改版本号，不生成发布说明，不调整打包产物；待 1.5.6 进入发布流程后再按发布规范整理变更清单。

## 本次加固范围

1. 单点登录 OIDC 令牌验证
   - OIDC/Casdoor 配置必须提供 Issuer。
   - 回调流程使用 `id_token` 验签后的 Claims，不再直接信任未验签 JWT Payload。
   - 校验 Issuer、Audience、过期时间和 Nonce，降低伪造回调与重放风险。

2. 登录态与会话缓存
   - 浏览器端认证 Token、过期时间和刷新状态从 localStorage 收敛到 sessionStorage。
   - 保留一次性兼容迁移，读取到旧缓存后迁移并删除旧 localStorage 值。
   - 请求、刷新、预览画布和 WebSocket 入口统一从认证缓存读取 Token。

3. 密码重置
   - 管理员重置本地账号密码后返回一次性临时密码。
   - 临时密码由 `SecureRandom` 生成，覆盖大小写、数字和特殊字符，并复用密码策略校验。
   - 单点登录账号仍禁止重置本地密码。

4. API 文档入口与安全响应头
   - Swagger、Knife4j、WebJars 文档入口不再匿名放行。
   - 后端与 Nginx API CSP 去除 `unsafe-inline`、`unsafe-eval`，限制 `object-src` 和 `base-uri`。

## 已知后续项

- 系统设置中的默认密码配置和用户管理页默认密码提示仍需要按产品方案补齐；当前分支不夹带该功能，避免偏离安全加固目标。
- SSO 端点当前允许企业内网 IdP 地址。若未来要对 SSRF 做更强约束，需要提供“允许内网身份源”的显式配置或网段白名单，不能直接按公网回调规则一刀切拦截。
- 进入 1.5.6 发布阶段后，需要将本记录整理进正式 Release Notes，并补齐离线包 SQL/升级说明。

## 验证建议

- 后端定向测试：SSO 令牌验签、SSO Token 过期时间、用户临时密码、白名单与安全响应头。
- 前端验证：登录、刷新 Token、普通用户门户入口、大屏预览、WebSocket 初始化、用户重置密码提示。
- 部署验证：直连后端与 Nginx 代理环境均检查 API CSP 响应头。
