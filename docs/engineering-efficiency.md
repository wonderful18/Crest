# 研发效能指标

Crest 内置研发效能演示资源，用于展示需求流动、交付效率、容量投入、工程活动和质量风险。演示数据只用于验证页面、图表和数据链路；接入生产数据时，应以企业自身管理口径为准。

## 指标域

| 指标域 | 典型指标 | 数据来源 |
| --- | --- | --- |
| 需求流动 | 需求吞吐、需求周期、等待时长、WIP、累积流 | 需求管理系统 |
| 交付计划 | 计划完成率、延期需求数、批次健康度 | 项目管理、发布计划 |
| 容量投入 | 人均并行需求、投入分布、工时分类 | 工时系统、排期系统 |
| 工程活动 | PR 合并时长、评审等待、构建成功率、部署频率 | Git、CI/CD、发布系统 |
| 质量风险 | 缺陷密度、线上事件、返工率、变更失败率 | 缺陷系统、事件系统 |

## 建模要求

接入真实数据时至少准备以下主键和时间字段：

- 需求唯一标识、需求类型、优先级、状态、创建时间、关闭时间；
- 状态流转记录，包含进入时间和离开时间；
- 项目、批次、团队、负责人和所属组织；
- 工时或投入记录，包含人员、日期、类别和耗时；
- PR、构建、部署、缺陷和事件的关联需求标识。

没有状态流转历史时，不应计算等待时长、阶段耗时、WIP 和累积流；可以先展示吞吐、存量、计划完成率等基础指标。

## 口径要求

- 指标名称、分母、分子和时间范围必须在数据集或说明字段中固定；
- 完成率类指标使用 `完成数 / 计划数`，结果超过 100% 时应明确业务含义；
- 周期类指标建议同时提供 P50、P80 或 P90，避免只看平均值；
- 等待时长要说明起止状态，例如“创建到进入开发”或“待开发到开发中”；
- 返工和线上事件必须有可审计的判定规则。

## 数据接入建议

先按主题建设宽表或视图，再在 Crest 中创建数据集：

| 主题 | 建议对象 |
| --- | --- |
| 需求流动 | `fact_requirement_flow` |
| 状态流转 | `fact_requirement_status_history` |
| 项目批次 | `fact_project_release` |
| 工时投入 | `fact_workload` |
| 工程活动 | `fact_engineering_activity` |
| 质量风险 | `fact_quality_event` |

每张表应包含组织、团队、项目和时间维度，便于图表筛选和钻取。

## 使用边界

研发效能指标用于发现瓶颈和趋势，不应直接作为个人绩效排名。生产环境接入前，应由研发管理、项目管理和数据治理负责人共同确认指标定义、数据质量和访问权限。
